# ADR-003: 演示数据生成采用异步 Job 模型

## 状态
ACCEPTED

## 背景

MVP 需要支持可配置演示数据生成，至少覆盖小样例、万级、百万级三档，并向用户展示阶段状态：初始化、生成、写入、统计、完成或失败。

Spec 开放问题 OQ-005 要求决定百万级演示数据生成是同步执行、异步任务执行，还是根据环境自动降级。

同步生成在小样例下体验简单，但在万级、百万级数据下可能导致 HTTP 请求超时、前端无响应、用户无法感知进度，也难以展示失败原因。

## 决策

采用异步 Job 模型生成演示数据。

API 设计：

- `POST /api/demo-data/jobs`：创建生成任务，立即返回 `jobId`。
- `GET /api/demo-data/jobs/{jobId}`：查询任务状态、进度、摘要或失败原因。

任务状态：

```text
pending -> initializing -> generating -> writing -> summarizing -> completed
                                      \-> failed
```

数据生成服务分批写入 MySQL，并周期性更新 `big365_demo_jobs` 中的 `status`、`progress`、`summary_json`。

## 后果

正面影响：

- 支持万级和百万级数据生成时的进度展示。
- 避免 HTTP 长请求超时。
- 便于前端轮询展示阶段状态。
- 失败时可记录失败原因，满足可诊断性要求。

负面影响：

- 后端需要异步执行配置、Job 表和状态管理。
- 前端需要轮询任务状态。
- 需要处理重复触发、任务失败、中断恢复等边界情况。

缓解措施：

- MVP 先实现单机内异步线程池，不引入外部任务队列。
- 限制并发生成任务数和单次最大记录数。
- 文档说明百万级生成的资源要求和可能耗时。
- E2E 默认验证小样例生成，万级/百万级作为可选验收。
